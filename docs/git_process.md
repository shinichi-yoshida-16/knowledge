# Git操作手順・チートシート
## 1. 目的・概要
### 1.1 本資料の目的
- Gitの基本操作・運用手順を忘備録として記す
- よく使うコマンドを目的別に整理し、必要な時にすぐ引けるチートシートとする

### 1.2 Gitの概要
- 分散型バージョン管理システム
  - ローカルリポジトリで変更履歴を管理し、リモートリポジトリ(GitHub等)と同期する
- 主な操作対象
  - ワーキングツリー(作業ディレクトリ) → インデックス(ステージ) → ローカルリポジトリ → リモートリポジトリ
- 参考資料
  - https://git-scm.com/book/ja/v2
  - https://git-scm.com/docs

## 2. 初期設定
### 2.1 インストール確認
- > git --version

### 2.2 ユーザー情報の設定(初回のみ)
- > git config --global user.name "氏名"
- > git config --global user.email "メールアドレス"
- 設定内容の確認
  - > git config --list

### 2.3 リポジトリの取得
- 新規作成
  - > git init
- 既存リポジトリの取得
  - > git clone <リポジトリURL>

## 3. 基本操作(日常の作業フロー)
### 3.1 状態確認
- > git status       # 変更ファイル・ステージ状況の確認
- > git diff          # 未ステージの変更差分を確認
- > git diff --staged # ステージ済みの変更差分を確認

### 3.2 変更のコミット
- > git add <ファイル名>     # 特定ファイルをステージ
- > git add .                # 変更を一括ステージ
- > git commit -m "コミットメッセージ"
- > git commit -am "コミットメッセージ"   # 追跡済みファイルの変更をadd+commit(新規ファイルは対象外)

### 3.3 履歴確認
- > git log                  # コミット履歴の表示
- > git log --oneline --graph --all   # 1行表示・ブランチ構造つき
- > git show <コミットハッシュ>        # 特定コミットの詳細差分

## 4. ブランチ操作
### 4.1 ブランチの基本
- > git branch                    # ローカルブランチ一覧
- > git branch -a                 # リモート含む全ブランチ一覧
- > git branch <ブランチ名>        # ブランチ作成
- > git switch <ブランチ名>        # ブランチ切り替え(推奨、checkoutより意図が明確)
- > git switch -c <ブランチ名>     # 作成と同時に切り替え
- > git branch -d <ブランチ名>     # マージ済みブランチの削除
- > git branch -D <ブランチ名>     # 未マージでも強制削除

### 4.2 命名規則の例
- feature/xxx: 機能追加
- fix/xxx: バグ修正
- hotfix/xxx: 緊急修正
- chore/xxx: 雑務・設定変更

## 5. リモート操作
### 5.1 リモートリポジトリの管理
- > git remote -v                          # 登録済みリモート一覧
- > git remote add origin <リポジトリURL>  # リモート追加

### 5.2 取得・送信
- > git fetch                # リモートの最新情報を取得(ローカルには反映しない)
- > git pull                 # フェッチ+マージ(またはrebase設定時はrebase)
- > git pull --rebase        # ローカルコミットをリモート最新の上にリベースして取り込む
- > git push                 # ローカルの変更をリモートに反映
- > git push -u origin <ブランチ名>   # 初回push時に上流ブランチを設定
- > git push origin --delete <ブランチ名>   # リモートブランチの削除

## 6. コミットの修正・取り消し
### 6.1 直前コミットの修正
- > git commit --amend                # 直前のコミットメッセージ・内容を修正
- > git commit --amend --no-edit      # メッセージを変えずにファイルだけ追加修正
- 注意: push済みの共有コミットをamendすると履歴が書き換わるため、共有ブランチでは避ける

### 6.2 変更の取り消し
- > git restore <ファイル名>            # ワーキングツリーの変更を破棄(未ステージ)
- > git restore --staged <ファイル名>   # ステージを解除(ワーキングツリーの変更は保持)
- > git checkout -- <ファイル名>        # 旧コマンド(restoreと同等、参考)

### 6.3 コミットの取り消し
- > git reset --soft <コミット>    # コミットを取り消し、変更はステージ済みのまま保持
- > git reset --mixed <コミット>   # コミットを取り消し、変更は未ステージで保持(デフォルト)
- > git reset --hard <コミット>    # コミットと変更内容を完全に破棄(要注意、復元不可に近い)
- > git revert <コミット>          # 指定コミットを打ち消す新規コミットを作成(共有ブランチで安全)

## 7. マージ・リベース
### 7.1 マージ
- > git switch main
- > git merge <ブランチ名>         # 対象ブランチをmainに取り込む
- コンフリクト発生時
  - 該当ファイルを編集し、`<<<<<<<` `=======` `>>>>>>>` のマーカーを解消
  - > git add <解消したファイル>
  - > git commit                  # マージコミットを作成して完了

### 7.2 リベース
- > git switch <作業ブランチ>
- > git rebase main                # 作業ブランチの土台をmain最新に付け替え
- コンフリクト発生時
  - 該当ファイルを編集して解消後
  - > git add <解消したファイル>
  - > git rebase --continue
  - 中断する場合
    - > git rebase --abort
- 注意: push済みの共有ブランチをrebaseすると履歴が変わるため、force push(`git push --force-with-lease`)が必要になり、他者の作業に影響する可能性がある。個人の作業ブランチのみで使用する

## 8. スタッシュ(作業の一時退避)
- > git stash                     # 作業中の変更を一時退避
- > git stash list                # 退避一覧の確認
- > git stash pop                 # 直近の退避を復元して削除
- > git stash apply                # 退避を復元(スタッシュ自体は残す)
- > git stash drop                 # 指定スタッシュを削除

## 9. タグ
- > git tag                        # タグ一覧
- > git tag <タグ名>                # 軽量タグの作成(現在のコミットに)
- > git tag -a <タグ名> -m "メッセージ"   # 注釈付きタグの作成
- > git push origin <タグ名>        # 個別タグをpush
- > git push origin --tags         # 全タグをpush

## 10. その他よく使う操作
### 10.1 特定ファイルの履歴・差分
- > git log -p <ファイル名>         # ファイル単位のコミット履歴+差分
- > git blame <ファイル名>          # 各行の最終変更コミット・作成者を確認

### 10.2 未追跡ファイルの整理
- > git clean -n                   # 削除対象の未追跡ファイルを確認(dry-run)
- > git clean -f                   # 未追跡ファイルを削除(要注意)
- > git clean -fd                  # 未追跡ディレクトリも含めて削除(要注意)

### 10.3 特定コミットの変更のみ取り込む
- > git cherry-pick <コミットハッシュ>   # 他ブランチの特定コミットを現在のブランチに適用

## 11. トラブルシューティング
### 11.1 コンフリクトを解消したい
- 対象ファイルを開き、`<<<<<<<`/`=======`/`>>>>>>>` のマーカー箇所を手動で修正
- 修正後 `git add` → マージ中なら `git commit`、リベース中なら `git rebase --continue`

### 11.2 直前のpushを取り消したい(まだ他者が取り込んでいない場合)
- > git revert <コミット>
- > git push
- 履歴を書き換える場合(自分専用ブランチ限定)
  - > git reset --hard <戻したいコミット>
  - > git push --force-with-lease

### 11.3 マージ・リベースを中断してやり直したい
- > git merge --abort
- > git rebase --abort

### 11.4 コミットメッセージを間違えた(未push)
- > git commit --amend -m "正しいメッセージ"

### 11.5 誤ってmainに直接コミットしてしまった
- 1. 現在の変更を新規ブランチへ退避
   - > git branch <新ブランチ名>
- 2. mainを直前の状態へ戻す
   - > git reset --hard origin/main
- 3. 新ブランチに切り替えて作業継続
   - > git switch <新ブランチ名>

## 12. 用語・注意点まとめ
- ワーキングツリー: 実際にファイルを編集する作業ディレクトリ
- インデックス(ステージ): コミット対象として登録した変更の一時置き場
- HEAD: 現在チェックアウトしているブランチ/コミットを指すポインタ
- force push(`--force`/`--force-with-lease`)は共有ブランチの履歴を破壊しうるため、個人ブランチ以外では使用しない
- `reset --hard`・`clean -f`は変更を復元困難な形で削除するため、実行前に`git status`/`git diff`で対象を必ず確認する

### 12.1 branch(ブランチ)とは
- コミット履歴の流れを分岐させる仕組み。実体は「特定のコミットを指す軽量なポインタ」で、コミットするとそのブランチのポインタが自動で最新コミットに進む
- 複数人・複数機能の並行開発を、互いに影響させずに進めるための単位
  - 例: `feature/xxx`(機能追加)、`fix/xxx`(バグ修正)などを個別ブランチで作業し、完成後に`main`へマージする
- 「main」も「master」も、この仕組みの上に乗る一つのブランチ名にすぎない(特別な種類のブランチではない)

### 12.2 main と master の違い
- 技術的な違いはなく、どちらも「リポジトリのデフォルトブランチ(通常は本番相当のコードを置く基幹ブランチ)」に付けられる名前(慣習上の呼び名)の違いにすぎない
- 歴史的経緯
  - Gitの初期設定では長らく`master`がデフォルトブランチ名だった
  - 2020年前後、GitHub/GitLab/Bitbucket等の主要サービスやGit本体が、奴隷制を想起させる用語(master/slave)を避ける流れを受けて、新規リポジトリのデフォルト名を`main`に変更した
  - 現在GitHubで新規作成するリポジトリのデフォルトブランチ名は`main`
- 実務上の注意点
  - 2020年より前に作られた既存リポジトリは、`master`のまま運用されている場合がある(自動では変わらない)
  - どちらの名前が使われているかはリポジトリごとに異なるため、`git branch`や`git branch -a`で実際のデフォルトブランチ名を都度確認する
  - 本資料の例では`main`を用いているが、対象リポジトリが`master`運用の場合は読み替える
- ブランチ名の変更方法(必要な場合)
  - > git branch -m master main            # ローカルブランチ名の変更
  - > git push -u origin main              # 新ブランチ名をリモートにpush
  - > git push origin --delete master      # 旧ブランチをリモートから削除
  - リモート側(GitHub等)のデフォルトブランチ設定も、リポジトリのSettings画面で`main`に変更する必要がある
